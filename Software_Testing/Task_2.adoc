== INTRODUCTION

This document describes the approach and methodologies used by the testing team to plan, organize and perform the testing activities for the NCAA Statistics Console Application. The application processes historical NCAA basketball finals data and responds to search queries from script files. It is a C# console application developed as a coursework project for the Software Engineering program at Yanka Kupala State University of Grodno.

== SCOPE OF WORK

=== Components and Functions to be Tested

1. File selection module (SelectFiles method)
2. Data import and normalization (LoadDataContent method)
3. Sorting algorithm (NCAAGameSort method)
4. Command processing module:
   * Year command processing
   * Titles command processing
   * Margin command processing
5. Logging and output handling (WriteOutput method)
6. Program startup (Boot method)

2. Application shouldn't have known bugs (issues) with severity Blocker and Critical at the time of Final Release.

== TEST STRATEGY

The Test Strategy presents the recommended approach to test the NCAA Statistics Console Application. The Test Plan describes what (components and functions) will be tested – Test Strategy describes how the application will be tested.

The main goal of current phase is testing the NCAA Statistics Console Application functionality according to the functional requirements.

Application will be tested using a "black box" approach, which is based on the functional requirements without knowledge of the internal structure or program source code.

=== Entry Criteria

The Testing Team may suspend partial or full-testing activities on a given build if any of the following occurs:

1. It is impossible to compile the application successfully.
2. There is a fault with a feature that prevents its testing.
3. New claimed functionality doesn't work or works improperly.
4. A severe problem has occurred that does not allow testing to continue.

=== Bug Severity Definitions

* Blocker – Application crash or cannot be executed
* Critical – Data corruption/loss, a problem in major functionality, no workaround is known
* Major – Major functionality partially works, no workaround is known
* Minor – A problem with workaround, secondary features do not work properly
* Trivial – Cosmetic flaw

=== Testing Types

==== Function Testing

Function testing of the NCAA Statistics Console Application focuses on verifying all requirements for the test that can be traced directly to use cases or business functions.

[cols="1,4", options="header"]
|===
| Test Objective | Ensure proper functionality of NCAA data processing, including data import, sorting, command processing, and log generation
| Technique | Execute each use case with valid and invalid data to verify: The expected results occur when valid data is used. The appropriate error messages are displayed when invalid data is used. Each business rule is properly applied.
| Completion Criteria | All planned tests have been executed. All identified defects have been addressed.
|===

==== User Interface Testing

User Interface testing for console application verifies proper command-line interaction.

[cols="1,4", options="header"]
|===
| Test Objective | Verify proper console interaction: menu selection, command processing, and output formatting
| Technique | Test all console interactions with valid and invalid inputs to verify proper responses
| Completion Criteria | Console interactions work as expected according to specification
|===

==== Regression Testing

The goal of Regression Testing is to make sure that previously fixed bugs do not appear again.

[cols="1,4", options="header"]
|===
| Test Objective | Verify that previously fixed bugs did not affect product quality
| Technique | Re-execute relevant Function Test cases after bug fixes
| Completion Criteria | All relevant test cases pass without failure
|===

== TEST LEVELS

=== Smoke Test

Smoke Test is performed to quickly assess the readiness of the Product for further deeper and more thorough testing.

[cols="1,4", options="header"]
|===
| Test Objective | Verify basic application functionality: file selection, data loading, and simple command execution
| Test Cases | 
* Select file group A and verify successful execution
* Process a simple year command and verify output
* Verify log file is generated correctly
| Completion Criteria | Basic functionality works without critical errors
|===

=== Critical Path Test

Critical Path Tests are performed after the Smoke Test is passed.

[cols="1,4", options="header"]
|===
| Test Objective | Find bugs that could affect the major functionality of the application
| Test Cases |
* Year command with valid year (type 1 and 2)
* Year command with invalid year
* Titles command with school that exists
* Titles command with school that doesn't exist
* Margin command with valid range
* Margin command with invalid start year
| Completion Criteria | Major functionality works as expected for all critical paths
|===

=== Extended Test

Extended Test's goal is to find bugs related to non-typical usage scenarios.

[cols="1,4", options="header"]
|===
| Test Objective | Find issues with edge cases and boundary conditions
| Test Cases |
* Margin command with numYears exceeding available data
* Very large NCAA data files
* Special characters in school names
* Boundary year values (min/max)
* Empty command files
| Completion Criteria | Application handles edge cases gracefully with appropriate error messages
|===
